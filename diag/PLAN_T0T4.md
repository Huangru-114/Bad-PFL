## 0. 术语（先统一，否则整份报告不可读）

上游任务书用 **A / C** 指「可洗成分 / 不可洗成分」，而 `exp1_persistence.csv` 的
**A / B / C 是触发器重算模式**。同名不同义，本项目一律按下表：

| 记号 | 含义 |
|---|---|
| **W** | washable，被良性训练洗掉的那部分能力 |
| **P** | persistent，200 轮良性训练后仍存活的那部分 |
| **臂 A** | frozen δ + online ξ（与臂 B 同一个 run） |
| **臂 B** | fully frozen trigger（与臂 A 同一个 run） |
| **臂 C** | online δ + online ξ —— **上界对照，独立的另一个 run** |

## 1. 已核实的事实

**⚠️ 全部 n_seed = 1**（B2 的 config 写 `seeds: [0,1]`，但只有 `s0` 跑了）。
按用户决定：**结论一律降级为探索性**，正文必须写明「单 seed，误差条为轮间/客户端间离散度，
不是重复实验误差」。

### 1.1 B2 持续性（`results/exp1_persistence.csv`，已入库）

设定：40 client · 每轮选 8 · ResNet-18 · `local_steps=15` · α=0.5 ·
`total_round=400` · 攻击窗口 `[140, 200)` · `bad_num=4` · `poison_rate=0.1`。
即「植入到高位 → 第 200 轮停攻 → 纯干净训练 200 轮」。

| 臂 | 起点 (r=0) | 尾段 r≥50 均值 | 尾段 sd | 斜率 /100轮 | t |
|---|---|---|---|---|---|
| A frozen δ + online ξ | 0.6174 | 0.3941 | 0.0413 | −0.0265 | −1.64 |
| **B fully frozen** | 0.6259 | **0.4133** | 0.0320 | −0.011 | **−0.86** |
| C online δ+ξ（上界） | 0.6201 | 0.4624 | 0.0582 | +0.065 | +3.19 |

臂 B 分段均值：`r0 0.6259 → [0,30] 0.5179 → [30,60] 0.4293 → [60,130] 0.4192 → [130,200] 0.4041`

> 本节每个数都可从 `results/exp1_persistence.csv` 直接复算（尾段定义 = `r >= 50`）。

**结论 1 —— 上游任务书的「200 轮不衰减」前提不成立。**
实际是「**前 ~30 轮掉掉 0.23，之后进地板并停住**」。尾段斜率与 0 不可区分（t=−0.86），
外推 200 轮仅 −0.022，所以「进地板后不再衰减」这半句成立。
**但这不是措辞问题**：(a) 休眠容量预测「P 从头没动过」，而数据显示前 30 轮蒸发了 0.23。
要解释的现象是「**为什么存在一个 ~0.41 的地板**」，不是「为什么不衰减」。
→ T0 的载体分离窗口要据此定义，直接用 θ₂₀₀ vs θ₄₀₀ 会把「快速衰减段」和「地板段」混在一起。

**结论 2 —— 地板对冻结触发器就可用。**
上界（生成器一直在线）0.4624 vs 全冻结 0.4133，**溢价仅 +0.049 ≈ 1 个轮间 sd**。
持续的东西**不是**「会移动、需要攻击者追踪的目标」。

**结论 3 —— 在线重算 ξ 无收益、略有害。**
A−B = **−0.0193 ± 0.0026**（同 run 配对，t=−7.36）。
→ 「全程用冻结 ξ」这个操作决定是对的，但理由应写「冻结 ξ **不劣于**在线 ξ」，不是「两者相同」。

**⚠️ 臂 C 的正确读法**：它是**上界对照**（`run_exp1.py` 里 C 线注释原文
"upper bound"），**不是**臂 B 的配对消融。它是独立的另一个 run，
`--generator-online-from 140` 从攻击窗口内就改变了生成器策略，
实测 `round_0200/global.pt` 的 hash 与 A/B run **已经不同**。
所以 **B−C 不能用来隔离「在线 δ 的收益」**；它只能读作「攻击者的上界」。
另外臂 C 自身的正斜率还压着第二个混杂：**生成器多训了 200 轮**（收敛）
vs **模型变得更可利用**——单看 C 臂分不开，拆它需要实验 F 的 (s,t) 矩阵。

## 3. 三个互斥假设与可证伪预测

| | 机制 | T0 预测 | T1 预测 | T2 预测 |
|---|---|---|---|---|
| **(a) 休眠容量** | 后门占据良性任务基本不用的参数，良性训练够不着 | P 位移 ≈ 噪声底，且 **≪** W | P 落在 g_ben **低分位** | 符号一致率 **≈ 50%**（正交） |
| **(b) 对齐共址** | 后门与主任务共享参数，良性训练无意中维持它 | P 位移大但 ASR 不掉 | P 落 **高分位** | **> 50%**（同向） |
| **(c) 函数平坦** | 后门不在特定参数值里，是宽盆里的函数性质 | P 位移大且与 W 相当 | 无特定预测 | 无特定预测 |

> （overlap 不对口径、缺基线、chance 未报、clamp 不忠实），不足以削弱 (b)。
> 而 §11 的 T3 反而给了 (b) 一些正面证据。**这一格现在是开放的。**
> **臂 C 不再作为 (a)/(b)/(c) 的证据**（见 §1.1 的读法警告）。判 (a) 生死靠 T0。

### 依赖顺序

```
Stage 0（免费）  T0 相对比较 + T2 粗粒度   ← 可能当场杀死 (a)
Stage 1（GPU）   干净基线 run × 2 seed      ← 一次同时给 P0.2 判别格 + T0 噪声底
Stage 2（条件）  (a) 活 → T1 → T4  /  (a) 死 → T3
```

**T0 不依赖噪声底也能出结论**：若 P 位移与 W **相当**，(a) 当场死，不需要绝对基准。

## 5. 与防御设计的连接

| 结论 | 防御含义 | 分层结构（Client→Edge→Cloud）的角色 |
|---|---|---|
| **(a)** | 提前占位（TrojanDam 类）**有对象**：攻击前用 flood/正则占满低 g_ben 坐标 | Edge 层可聚合 g_ben 统计，比单客户端更可靠地识别冗余容量 → 分层是**优势** |
| **(b)** | 参数空间路线**死**（剪枝/占位必伤 MTA）。转特征层对抗训练 / 不变性学习 | 无特殊作用 |
| **(c)** | 参数空间**定点操作全部无效**（剪枝/掩码/占位原理上够不到）。转蒸馏 / 平滑 / 改变训练动力学让盆变窄 | Edge 层的多次聚合**本身就是平滑** —— 可能解释「引入 edge 层削弱 ASR」的观察 |

**两条不依赖判定、现在就能写进论文的结论：**

1. **防御不需要防自适应重优化的攻击者。** 上界溢价仅 0.049（§1.1 结论 2），
   在线重算 ξ 甚至有害（结论 3）。**防住固定触发器就够** —— 实质降低了防御的难度要求。
2. **检测不是瓶颈，决策阶段才是。** 攻击不隐蔽（`l2` AUC → 1.0，§1.4），指标不缺；
   缺的是聚合时怎么处置。「主动式防御」的价值不在**发现**恶意端，而在**降低单位曝光的
   植入效率** —— 与 `HANDOFF.md §2` 的杠杆 `E = Σ I·s·‖g‖/D` 是同一条主线，应合并。

## 6. 数据位置与已知坑

### checkpoint（集群，`checkpoints/` 是 gitignore 的）

```
checkpoints/attack_a0.5_s0_e1b_persist_s0/          ← A/B run，T0 用这个
    round_{0050,0100,...,0400}/  global.pt · client_*.pt · generator.pt
    global.pt · client_*.pt（全 40 个）· generator.pt · delta.pt · meta.json   ← save_run 末尾
checkpoints/attack_a0.5_s0_e1b_persist_online_s0/   ← C run（上界），T0 不用
```

快照机制：`_base_command` 不传 `--snapshot-every` → 回落 `cfg.exp_f.snapshot_every = 50`
→ `build_grid(400,50) = [50,…,200,…,400]`，**stop 轮与 stop+200 轮都在网格上**。
`SnapshotRecorder` 每个网格点存 global + 12 个选中客户端 + generator。

### 坑

1. **`round_0400` 只有 3 个 client**，不是数据丢失：客户端快照在「该客户端**参与**时」才写，
   而 grid 400 是最后一轮，只有那轮参与的 ~8/40 来得及。**用 run 根目录那份**（全 40 个）。
2. **客户端快照有 staleness**：存的是「上次参与后的模型」。40 client 选 8 → 期望 ~5 轮。
   → **T0 主分析用 `global.pt`（staleness=0）**，客户端本地模型只做稳健性检查。
3. **模型口径错位**：B2 的 ASR 是 **benign 个性化模型**口径，而参数位移在 **global** 上测。
   两者不是同一个模型，**正文必须声明**，不能装作没有。
4. **T1 必须 Σ\|g\| 不是 Σg**。Σg 再取绝对值会让「被使用但符号震荡」的坐标 ≈0，
   于是 T1 退化成 T0 的重复测量，**失去区分 (a)/(c) 的能力**。
5. **新埋点不能消耗 RNG**，否则重跑轨迹会漂（`--generator-online-from` 就是这么让
   θ₂₀₀ 都变了的）。正确范式已有：`snapshots.py`「只做 I/O，不消耗 RNG」、
   `track.py` 的 `preserve_rng_state`。
6. **BN buffer** 要显式决定是否计入 θ 并声明。主分析用可训练参数，附录单独报 BN buffer
   的 Δ 统计量 —— 若 BN 承载大量后门能量，这本身就是结果。
   注意 **FedBN 一直开着，BN 从不聚合**（见 `CLAUDE.md` / `README §4b`）。
7. **图里绝不出现 CJK**（`assert_no_cjk_in_figure` 会拦）。
8. **不为让结果好看而调 k / 分位阈值 / 载体定义**；所有 k 的结果都要报。

## 9. T0 结果（2026-09-04，集群实测，`results/t0/`）

run：`attack_a0.5_s0_e1b_persist_s0`，全局快照网格 `[50,100,…,400]`，
11,173,962 个可训练参数（ResNet-18）。**n_seed = 1，探索性**（§1 的降级仍然适用）。

### 9.0 两条口径修正（做完 T0 才发现，已改进代码）

1. **参照窗口只能取到一部分。** `snapshot_every=50` 的网格上**没有 140**，
   所以拿不到完整的植入窗口 `[140,200)`，只能用 `150→200`（60 轮里的 50 轮）。
   `attack_reference` 因此退化取"落在植入阶段内最长的窗口"，并在判词里标注
   `attack_window_is_full=false`。**退化取的是更短的窗口 → 参照尺度偏小 → 比值偏大**，
   这个方向必须随数字一起报。要拿完整的一格，下次 B2 的快照网格得踩到 `attack_start`。

2. **FedBN 冻结的不只是 BN buffer，还有 BN 仿射参数。** 10 个窗口的
   `bn_affine_l2_delta` 与 `bn_buffer_l2_delta` **全部恰好为 0**，且
   ‖θ_bn‖ 恒 = **69.282 = √4800** —— 正是 `weight=1, bias=0` 的初始化值。
   于是原来的主口径 `trainable`（含 bn_affine）把分母从 43.3 抬到 81.7，
   **凭空稀释相对位移约 1.9 倍**，分子一点不变。新增 `aggregated_*`
   （= weight + bias，即真正参与聚合的那部分）作为主口径，两份都进 CSV。
   > 换分母**不影响结论方向**：比值 1.35（trainable）vs 1.33（aggregated）。
   > 这是 §4b「FedBN 下全局模型 BN 永不更新」的**逐坐标实证**，此前只有间接证据。

### 9.1 位移剖面（`aggregated` 口径，相对位移 = ‖Δθ‖/‖θ‖）

| 窗口 | 轮数 | 阶段 | rel(aggregated) | rel(trainable) | cos(θ, Δθ) |
|---|---|---|---|---|---|
| 150→200 | 50 | 植入（部分） | **0.1175** | 0.0612 | 0.070 |
| 200→250 | 50 | 干净 | **0.1029** | 0.0545 | 0.067 |
| 200→400 | 200 | 干净 | **0.1562** | 0.0827 | 0.080 |
| 250→300 | 50 | 干净 | 0.0793 | 0.0426 | 0.050 |
| 300→350 | 50 | 干净 | 0.0530 | 0.0286 | 0.028 |
| 350→400 | 50 | 干净 | 0.0374 | 0.0203 | 0.020 |

**结论 T0-1 —— 干净训练的改写量与植入阶段相当，甚至更多。**
全段比值 `0.1562 / 0.1175 = **1.33**`；**同时长**比较（各 50 轮）
`0.1029 / 0.1175 = **0.876**`。两个都 ≥ `RATIO_COMPARABLE = 0.5`。
即：攻击停止后的 200 轮里，参数被改写的幅度不小于植入它们的那段，
**而 ASR 停在 0.41 的地板不再下去**。

**结论 T0-2 —— 位移是方向改写，不是缩放。**
`cos(θ, Δθ) = 0.02–0.08`（近似正交）；`sign_agreement(θ, Δθ) = 0.505–0.527`
（≈ 随机符号）；`spearman(|Δθ|, |θ|) = 0.13–0.17`（弱正相关）。
所以不是"权重整体按比例长大"这种平凡漂移。

**结论 T0-3 —— 干净阶段的漂移是近似正交增量的随机游走，不是定向漂移。**
把 200→400 拆成 4 段：实测 ‖Δθ‖ = 6.755，各段**正交**时应为 6.355，
各段**同向**时应为 11.975 → **实测/正交 = 1.063**（同向/正交 = 1.884）。
良性训练没有朝某个固定方向持续推进 —— 与"进地板后 200 轮不再衰减"一致。

### 9.2 逐层：**没有任何一层是静止的**

21 个层（`bn_affine` 除外，它恒为 0）逐层比较"干净 200 轮 / 植入 50 轮"的相对位移：

    min 0.976 (conv1)   median 1.265   max 1.698 (linear)

**每一层**在干净阶段的位移都 ≥ 植入阶段（最小的 conv1 也有 0.976）。
位移最大的是 `layer3.*`（能量占比 top-3 合计 38%）与 `linear`（相对位移 0.263）。
→ **层粒度上不存在"良性训练够不着的休眠区"。**

能量集中度在两个阶段**几乎一样**（top 1% 坐标占 22.0%（植入）vs 22.2%（干净），
top 10% 占 69.3% vs 68.5%），所以也不是"干净训练只动了一小撮坐标"。

### 9.3 判词：(a) 未死，但被逼到很窄的地方

T0 **没有**、也不能判 (a) 的生死（它测全体坐标，(a) 讲载体子集）。它给出的是**约束**：

> (a) 休眠容量若要成立，后门载体 P 必须是一个**坐标粒度**的、位移显著低于全局
> 平均的小子集 —— 因为层粒度已经被排除，且干净阶段的整体改写量不低于植入阶段。

同时，**(c) 函数平坦得到了正面证据**（§3 的 (c) 预测就是"P 位移大且与 W 相当"）：
200 轮、相对幅度 0.156、方向近正交的随机游走都没把 ASR 打下 0.41。

⚠️ **口径声明**（坑 3，正文必须写）：位移在 **global** 模型上测，
B2 的 ASR 是 **benign 个性化模型**口径 —— 两者不是同一个模型。

### 9.4 这改了什么下一步

- **T3 平坦性现在有了具体数字可用**，而且它从"(a) 判死后才做"升级为**当下就该做**：
  往 θ₄₀₀ 上加**相对幅度 0.156** 的随机方向扰动（配随机方向对照），
  看 ASR 掉不掉。掉不动 = 宽盆 = (c)；掉得动 = 真实漂移方向有特殊性。
  这是 T0 直接喂出来的、代价最小的下一个实验。
  → **代码已就绪**：`diag/exp_t3.py`（用法见 `README §3.5f`），
  CPU 的标定一步不排队，GPU 的评估一步默认 dry-run。设计要点见 §10。
- **S1 载体分离仍是判 (a) 生死的唯一途径**（需要 `L_bd` 的梯度 → 集群）。
- **T1 的优先级下降**：它本是"(a) 存活才做"，而现在 (a) 的存活空间只剩坐标粒度，
  T1 的 Σ|g| 恰好就是坐标粒度的度量 —— 所以它变成 **S1 的伴随测量**，不是独立分支。
- **噪声底仍然缺**（Stage 1 的两条干净 run）。但注意：本次结论**不依赖噪声底** ——
  §4 早就写了"若 P 位移与 W 相当，不需要绝对基准"，走的正是这一支。

## 10. T3 的设计（代码已就绪，未跑；`diag/exp_t3.py`）

**问题**：T0 证明了干净训练把参数改写了 0.156（相对，aggregated 口径）而 ASR 停在
0.41 不再下去。那么这个地板是**参数空间里一个很宽的盆**，还是**真实漂移方向恰好特殊**？

```
随机方向、同幅度 -> ASR 也不掉       => 宽盆 => (c) 函数平坦
随机方向、同幅度 -> ASR 掉到迁移地板  => 良性训练在主动维持后门 => 更像 (b)
```

### 10.1 六个方向族（§4 要求的"必须配随机方向对照"）

| 族 | 构造 | 控制掉什么 |
|---|---|---|
| `zero` | 不动 | **自检锚点**：必须复现未扰动的 ASR/ACC |
| `gaussian_global` | 各向同性，只匹配全局范数 | 能量按层大小分配，逐层剖面**不**匹配 |
| `gaussian_layer_matched` | 逐层各向同性，逐层相对位移匹配真实漂移 | **主对照**：同幅度、同剖面、方向随机 |
| `shuffled` | 真实 Δθ 层内置换坐标 | 保幅度的边缘分布，打掉"是哪些坐标" |
| `sign_flipped` | 真实 Δθ 逐坐标翻符号 | 保幅度**与坐标**，只打掉方向相干性 |
| `real` | 真实 Δθ | 正对照 |

后三族把「幅度」「坐标身份」「方向相干性」逐个剥开 —— 只有一个高斯对照是不够的：
高斯同时改变了这三样，随便哪一样起作用都会被读成"方向不特殊"。

### 10.2 三条硬约束（都写进代码并被测试钉死）

1. **ASR 必须与 ACC 一起读。** 把模型打坏也能让 ASR 掉。`flatness_verdict` 在 ACC
   相对基线掉超过 `ACC_GUARD = 0.05` 时**拒绝**给该幅度下的任何 ASR 结论，
   并明说"不要读成扰动能消后门 —— 模型本身已经坏了"。**这是这个实验唯一能立住的读法。**
2. **扰动只加在 `aggregated` 参数上**，客户端自己的 BN 原样保留。FedBN 下全局模型的
   BN 恒不更新（§9.0 实测位移恰好为 0），扰动它等于做训练根本不会做的事。
3. **评估口径与 B2 那条 0.4133 的曲线一致**：每个客户端自己的个性化模型、
   自己的 test 分区、`recompute_asr_final.client_asr` 的原始触发器。
   默认只评良性客户端 —— 恶意端 ASR≈1.0，混进均值会把地板抬起来，
   而地板讲的是**受害者**模型上还剩多少。

### 10.3 跑之前先看 build 的标定自检

`--mode build` 是纯 CPU、不排队的。三条必须成立，否则整个对照不成立：

- `achieved_relative_displacement == target_relative`（浮点精度内）；
- `real` 族的 `cos_with_real_drift == 1`；
- `layer_profile_max_rel_dev` 对 `gaussian_layer_matched` / `shuffled` /
  `sign_flipped` / `real` ≈ 0，对 `gaussian_global` 明显 > 0。

该读数是**无量纲**的（`ratio_L / ratio_global − 1` 的最大绝对值），所以跨 multiplier
可比 —— 用绝对差会把 multiplier=2 上一个形状完美的扰动误报成偏差很大。

### 10.4 已知边界（跑之前就该知道）

- **扰动是"外加的"，不是训练出来的。** 真实漂移落在 SGD 可达的流形上，随机方向不是。
  若随机方向打掉了 ASR，这**不能**直接推出"良性训练在主动维持后门"——
  也可能只是"随机方向普遍比训练方向更伤模型"。ACC 闸门挡掉了最粗的那种情形，
  但挡不干净。真要分开，得看 T2 的符号一致率（Δθ 与 ∇L_bd 的夹角）。
- **n_seed 仍然是 1**（B2 只跑了 s0），随机族的三个 seed 只刻画扰动的随机性，
  **不是重复实验**。
- **`base_relative` 写在命令行里**（默认 0.156 = T0 实测值），不在代码里偷偷改；
  实测值与命令行给的差超过 0.01 时 build 会告警。

## 11. T3 结果（2026-09-05，集群实测，`results/t3/`）

设定：锚点 = **r=400 的个性化客户端模型**（36 个良性）；扰动加在 `aggregated`
参数上，各客户端自己的 BN 保留；ASR = target-排除的社区口径。
53 个配方 × 36 客户端 = 1908 格。**n_seed = 1，探索性**。

### 11.0 ⚠️ 先纠正两处我自己的错

**(1) 初版判词报的「宽盆」是错的，已修。**
`flatness_verdict` 的宽盆分支**只读随机族、根本没读 `asr_real`**，于是在 real
把 ASR 打到 0.055 的情况下仍然因为"随机族保留了 98%"而宣布宽盆。
现在主判据改为 real 与随机族在**同一个 ACC 代价**上的对比，并加了回归测试
（`test_verdict_calls_the_direction_special_when_only_real_erases`）。

**(2) 只按等位移幅度比是有混杂的，主判据已改成等 ACC 代价。**
1100 万维里随机方向几乎与损失面所有"陡"方向正交，所以"随机扰动范数 0.078 却
几乎不改变函数"近乎同义反复。实测直接坐实：同样 0.078 位移，随机族 ACC 只掉
0.002–0.008，real 掉 0.047 —— **两者根本没在同一个函数改变量上比较**。

### 11.1 主结果：等 ACC 代价（0.05）下的 ASR

基线（`zero` 格，即 200 轮良性漂移的终点）：**ASR 0.3637 · ACC 0.8242**。

| 方向族 | ASR@等代价 | 残留 | 用到的 multiplier 区间 |
|---|---|---|---|
| **real** | **0.0540** | **15%** | 0 – 0.5 |
| shuffled | 0.2462 | 68% | 0.5 – 1 |
| sign_flipped | 0.3403 | 94% | 1 – 2 |
| gaussian_global | 0.3424 | 94% | 2 – 4 |
| gaussian_layer_matched | 0.3993 | 110% | 2 – 4 |

**结论 T3-1 —— 残留后门不由位移幅度决定，由方向决定。**
付同样的干净准确率代价，沿良性方向继续走把 ASR 打掉 85%，而幅度等价的随机方向
只打掉 6%（`gaussian_layer_matched` 甚至略升，在噪声内）。
**这证伪了「任意同幅度扰动都出不了盆」的宽盆读法**（也就是我原来那句判词）。

**结论 T3-2 —— 效应不是客户端噪声。**
m=0.5 上逐客户端配对：real 比每个随机族都低，**36/36 个客户端全部同向**，
配对 t ≈ 19.4–19.7。而随机族之间的 seed 间 sd 只有 0.004–0.016。

**结论 T3-3 —— 擦除力在方向的相干性里，不在"哪些坐标"或"每个坐标动多少"。**
`sign_flipped` 保住了坐标身份**和**逐坐标幅度，只随机翻符号，结果几乎与纯高斯
一样无效（94% vs 94%）。`shuffled` 打乱坐标但保住幅度分布，反而更有效（68%）。
→ **仅仅"动对了坐标、动对了大小"不够；符号/相干结构才是携带信息的那部分。**

### 11.2 ⚠️ 锚点语义：`real` 是外推，不是复现

锚点是漂移**之后**的 r=400 模型，所以：

- `zero` 格 = 那 200 轮良性漂移**已经走完**的终点，ASR 0.3637 就是地板本身；
- `real` 格 = 沿同一方向**再多走**一段。

因此 T3 回答的是「继续沿良性方向走 vs 随便走」，**不是**「那 200 轮为什么没打掉」。
**尤其不能读成「普通良性训练能清除 Bad-PFL」** —— `zero` 格自己就是 200 轮良性
训练之后的结果，ASR 仍有 0.3637，与原文的 FT 消融一致。

### 11.3 T3 现在**不能**支持的三条

1. **不能**说"后门在/不在宽盆里"。随机方向在当前幅度上无效，只说明这些
   off-trajectory 方向无效，不构成对盆的几何刻画。
2. **不能**说"良性训练可清除 Bad-PFL"（见 §11.2）。
3. **不能**当作可部署防御。`Δ = θ₄₀₀ − θ₂₀₀` 需要预先知道未来 200 轮的漂移，
   部署时拿不到。当前 T3 属于**机制干预 / 因果诊断**，不是 defense。

### 11.4 假设改写（替换 §3 里对 T3 的期待）

原来的 (a)/(b)/(c) 三分对 T3 的产出已经不够用了，改用：

- **H1（已支持）**：后门残留**不只由参数位移幅度决定**。
- **H2（已支持，单锚点单 seed）**：良性优化方向对 Bad-PFL 后门的破坏力
  **不成比例地高于**同等 ACC 代价的随机方向。
- **H3（未测）**：这种擦除性质**能跨独立的良性轨迹泛化** —— 即换一条与该攻击
  run 无关的 clean run 得到的 Δ，作用在同一个中毒模型上，是否同样有效。
  **H3 成立才谈得上做成防御。**

与 §3 的关系：随机方向在等代价下打不掉后门，**削弱了"(c) 各向同性宽盆"**；
而"良性方向特别有效"更像是后门与主任务在**同一批方向**上耦合（(b) 的味道），
但 §1.2/§1.3 又显示干净模型对 δ 无响应。**这两条目前不融洽，别硬圆**，
需要 T2（Δθ 与 ∇L_bd 的符号一致率）来接。

## 12. §1.2 / §1.3 的口径审计（2026-09-05，读代码，未重跑）

起因：T3（§11）显示良性方向对后门有不成比例的破坏力（像 (b) 共址），而
§1.2/§1.3 说干净模型对 δ 毫无响应（像 (b) 死）。**两条对不上**，所以回头查
这两个早期实验的口径。查到 **5 个问题，其中 2 个零机时可修**。

### 12.1 F1 ⚠️ 触发器重建不忠实：末端 clamp（影响 §1.2，可能影响 §1.3）

```
fba.py:55   poison_data = mask*(poison_data + gen_trigger) + ~mask*data   # 没有 clamp
perturb.py  return out.clamp(pixel_min, pixel_max)                        # clamp 了
```

`pgd_attack` 的输出已经被 clamp 到 [0,1]，再加 δ（|δ|≤4/255）时，**凡是贴到
0/1 边界的像素，那部分 δ 会被削掉** —— diag 重建的触发器**系统性弱于真实攻击**。

这正是 `HANDOFF.md §5b` 记录的「perturb 分解路径低估 ASR」的一个**具体机制**
（§5b 当时只归因到"弱后门模型"，没有定位到 clamp）。

**削掉了多少，从来没测过。** 已补：`perturb.apply_perturbation` 新增
`clamp=False`（复现原口径）与 `diagnostics=` 出参，`clip_diagnostics` 给出
`clipped_fraction` / `clipped_l1_ratio` / clamp 前后的 L∞。
**下次跑 exp_e 必须把这几列落盘**，否则偏离仍然不可见。

### 12.2 F2 ✅ 零机时可修：`linf_realized` 被 summary 整列丢掉（§1.2）

`exp_e.evaluate_mode` 逐行记了 `linf_budget` / `linf_realized`，但
`analysis_e.summarize_e` 的 `metrics` 白名单里没有它们 —— 于是
`results/exp_e_summary.csv` 里**一列都没有**。已加回。
→ **对现有 `results/raw/exp_e_*.csv` 重跑 `summarize_e` 即可**，零 GPU。

### 12.3 F3 ✅ 零机时可修：`nat_rate` 从来没被汇总过（§1.3）

`exp_a.run_exp_a` 每行同时算 `overlap` 与 `nat_rate`，但
`results/summary/expA_summary.csv` 的 `metric` 列**全是 `overlap`**。

而这两个量回答的**不是同一个问题**：

| 量 | 问的是 |
|---|---|
| `overlap` | 加了 δ 的图片，在**特征空间**里的 k 近邻有多少属于目标类参照库 |
| `nat_rate` | 干净模型**把它判成目标类**的比例 |

§1.3 要支撑的命题是「干净模型对 δ 有没有可测响应」——**`nat_rate` 才是直接
读数**。→ 对同一批 raw CSV 跑 `summarize(..., metric="nat_rate")`，零 GPU。

### 12.4 F4 ⚠️ 缺"未扰动 query"基线，且三组全部**低于** chance（§1.3）

`NATURALNESS_GROUPS` 原来是 `(real, delta_only, delta_plus_xi, random_noise)`
—— **没有"query 不加任何扰动"这一组**。没有它，`delta_only=0.084` 与
`random_noise=0.073` 都无从解读：不知道 δ 到底把 query **推动了多少**，
只能说"δ 和噪声一样"。已加 `query_clean` 组（纯前向，零额外成本，需重跑 expA）。

更要紧的是 **chance level 从来没被报过**。`knn_overlap` 的随机基准 =
ref 在参照库里的占比 = `500 / (500 + 9×200)` = **0.2174**（`analysis.overlap_chance_level`）：

| 组 | overlap (α=0.5) | vs chance 0.217 |
|---|---|---|
| real | 0.817 | 远高于 |
| delta_plus_xi | 0.158 | **低于** |
| delta_only | 0.084 | **低于** |
| random_noise | 0.073 | **低于** |

→ §1.3 原话「实测 = 经验基率」**不准确**：三组都**低于**基率
（非目标类图片本来就更靠近 `other` 一侧）。正确说法是「δ 没有把 query 推过
chance，与同预算随机噪声不可分」——**而"推动了多少"仍待 `query_clean` 补测**。

### 12.5 F5 ⚠️ 负对照更强，且实测幅度从未记录（§1.3）

`metrics._make_transform` 不传 `noise_dist`，走默认 **rademacher**：逐元素 ±eps，
L∞ **恰好** = eps，是该预算下**最强**的随机噪声。而 δ = eps·tanh(·)，
|δ| ≤ eps 且通常**严格小于**。`perturb` 的 docstring 早就写明「两者是同预算，
不是同实测幅度」，但 **expA 的行里没有任何 linf 列**，所以实际差多少无人知道。

→ 「δ 与同预算随机噪声不可分」这句成立，但**不能**加强成「δ 不携带语义」：
δ 可能只是幅度更小。重跑 expA 时要把 δ 的实测 L∞/L2 一起落盘。

### 12.6 结论：§1.2/§1.3 现在该怎么引用

- **§1.2 的 E1（0.9994）稳**：后门足够强，clamp 削一点不改变结论。
- **§1.2 的 E2–E4（0.027–0.126）要降级**：那是**弱信号区**，恰恰是 clamp
  偏差影响最大的地方，而偏差大小未测。**「δ 无跨模型迁移性」暂时只能作为
  待验证项**，不能当既成事实去和 §11 的 T3 结果对撞。
- **§1.3 的"四个 α 一致"仍然有价值**（同一口径内部的一致性），但
  「**证伪了 Bad-PFL 原文的机制叙事**」这句**必须撤回到待验证**，
  直到 F3（nat_rate）与 F4（query_clean + chance）补上。

→ **§11.4 里那条「(b) 共址与 §1.2/§1.3 不融洽」的紧张关系，很可能不是真的
矛盾，而是 §1.2/§1.3 的口径问题。** 先做 F2/F3（零机时），再决定要不要重跑。
